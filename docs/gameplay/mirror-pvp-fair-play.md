## 1. 核心机制：镜像攻击完整数据流

```
玩家 A 玩 PvE 闯关 → 通关时刻布阵（命名 "X"）
   ↓ 触发 FeedLayoutCommand(玩家A.id, 布阵X)  [Subsystem 8 镜像 PvP]
   ↓ 异步
MirrorPool：把 X 加入"待匹配池"（保留 30 天）
   ↓ 触发
玩家 B 上线 → Player_CameOnline 事件
   ↓
FetchMirrorQuery(B.id, B.段位) → 抽取对手镜像
   ↓ 筛选规则
┌────────────────────────────────────┐
│ 1. 同段位 ±200 分优先                  │
│ 2. 段位差 > ±300 分直接拒绝匹配          │
│ 3. 24 小时内已被对手击败过的拒绝           │
│ 4. 30 天前布阵自动失效                  │
└────────────────────────────────────┘
   ↓
MirrorPvP_BattleInitiated(B, X)
   ↓ B 5 分钟内未反手布阵
AI 镜像兜底（难度 +50% 的 NPC 反手布阵）
   ↓ 模拟攻防
MirrorPvP_BattleResolved(胜负, 战报)
   ↓ 双写
玩家 B 战报中心 + 玩家 A 战报中心（被动接收）
```

## 2. 公平竞技 4 条强制约束详解

### 约束 1：镜像池只取 PvP 准入英雄

| 规则 | 实现 |
|---|---|
| PvP 准入池 = Gacha **R 角色全部** + Gacha **SR 角色少量** + **0 个 SSR 角色** | 在 `GachaPool` 数据模型上新增 `PvP_Eligible` 布尔字段 |
| SSR 角色**严禁**进入镜像池 | `FeedLayoutCommand` 处理器校验：布阵中含 SSR → 拒绝 + 玩家 A 收到友好提示 |
| PvP 准入池大小：**约 16–24 个 R + 8–12 个 SR**（随 MVP 16 角色扩展） | Subsystem 5（动物英雄）提供查询接口 `GetPvPEligibleHeroesQuery()` |

### 约束 2：PvP 段位独立（ELO 详解）

| 段位 | ELO 分段 | 镜像对手范围 | 玩家占比目标 |
|---|---|---|---|
| 青铜 I–III | 0–799 | 700–900 | 40% |
| 白银 I–III | 800–1199 | 800–1200 | 30% |
| 黄金 I–III | 1200–1599 | 1100–1500 | 15% |
| 铂金 I–III | 1600–1999 | 1500–1900 | 10% |
| 钻石 I–III | 2000–2399 | 1900–2200 | 4% |
| 大师 | 2400+ | 2200+ | 1% |

- **新玩家起始**：1000 分（白银 II）。
- **ELO 变化**：胜 +15 / 负 -10 / 平 ±0。
- **每日镜像上限**：10 局（防刷分）。
- **跨段位保护**：低段位玩家**永不被高 2 段以上**玩家镜像（哪怕高分玩家布阵过）。

### 约束 3：Gacha 英雄仅在 PvE 闯关中加成

| 战斗模式 | Gacha 英雄可用性 | 加成 |
|---|---|---|
| **PvE 闯关** | ✓ 全部（含 SSR） | SSR 数值 +30% / SR +15% / R +0% |
| **镜像 PvP** | ✓ 仅 PvP 准入英雄（约束 1） | R/SR 无数值加成（平衡 PvP） |
| **国联世界 BOSS** | ✓ 全部 | 同 PvE |
| **剧情副本 / 教学** | ✓ 全部 | 同 PvE |

实现：`HeroData` 上加 `PvP_Eligible` 字段 + `BattleMode` 上下文区分。Subsystem 5 提供 `GetEffectiveHeroStatsQuery(HeroId, BattleMode)`。

### 约束 4：战斗节奏 8 分钟硬性

| 项目 | 规则 |
|---|---|
| PvP 单局时长上限 | **480 秒（8 分钟）** 硬性 |
| 超时处理 | 自动判定为"平局"，双方均不扣分 |
| 跳过功能 | 双方均可"3 倍速 / 跳过"两档 |
| 断线超时 | 30 秒内未重连 → 自动托管 AI 操作（不算败） |

实现：`BattleTimer` 服务（Subsystem 8 子模块），客户端 / 服务端**双向计时**（防客户端修改）。

## 3. 镜像池匹配规则

### 3.1 拉取规则（FetchMirrorQuery 处理器）

```
输入：玩家 B 的 id、当前段位、最近 24h 镜像历史
输出：从镜像池筛选的对手布阵 X

筛选顺序：
1. 段位匹配：±200 分（钻石及以上 ±100 分）
2. 排除 24h 已用过的对手布阵
3. 排除自己 30 天内的布阵（防镜像自己）
4. 排除 7 天前已下架布阵
5. 优先选"活跃玩家"（最近 24h 内登录过）的布阵
6. 兜底：AI 镜像
```

### 3.2 镜像池维护

| 操作 | 触发者 | 时机 |
|---|---|---|
| 加入镜像池 | FeedLayoutCommand | PvE 通关 / 国联赛季结算后 |
| 移除镜像池 | 自动 / 手动 | 30 天过期 / 玩家主动下架 |
| 强制下架 | 系统 | 反作弊检测命中 / 玩家举报 |

## 4. AI 镜像兜底（PvE 难度 +50%）

当在线玩家不足时，启用 AI 镜像生成：

| 维度 | 规则 |
|---|---|
| 触发条件 | 镜像池空 / 同段位无可用布阵 |
| AI 难度 | 数值 +50%（对比 PvE 标准难度） |
| AI 风格 | 保守型（不开麦出招，但站位最优） |
| 玩家 ELO 变化 | 胜 +15 / 负 -10 / 平 ±0（与真人镜像一致） |
| 战报标注 | 显著标"AI 镜像"，**禁止**伪装真人 |

## 5. 战报回放与社交痕迹

### 5.1 战报回放数据流

```
MirrorPvP_BattleResolved 事件
   ↓ 双写
玩家 A 战报中心 + 玩家 B 战报中心
   ↓ 异步
玩家 B 上线 → BattleReportCenterUI
   ↓ 点击"查看战报"
从 Subsystem 8 的 MirrorConfig + BattleTimeline 重放
   ↓
可拖动时间轴 / 可分享链接（深链 + 防 URL 猜测）
```

### 5.2 战报分享

| 分享渠道 | 形式 |
|---|---|
| 游戏内 | 战报详情页 → "分享"按钮 → 生成长图 + 深链 |
| 微信 / X.com | 短链 + 缩略图（"X 击败了你的布阵，TA 的战力是..."） |
| 朋友圈 | 自动生成"战报卡片"图片 |

## 6. 反作弊与防高 R 碾压

### 6.1 服务端行为校验（Subsystem 11 存档/云）

| 异常行为 | 检测规则 | 处理 |
|---|---|---|
| 修改客户端时间 | 客户端 / 服务端时间差 > 5 秒 | 标记可疑 + 当局不计分 |
| PvP 准入英雄违规 | 战报中发现 SSR | 该局作废 + 玩家警告 |
| 频繁断线重连 | 1 小时内 > 3 次断线 | 当日禁止镜像攻击 |
| 段位异常飙升 | 24h 升段 > 300 分 | 进入人工审核池 |
| 同 IP 多账号 | 同一 IP 段下多设备镜像 | 警告 + 限流 |

### 6.2 客户端反作弊

- 客户端**仅持有战斗执行逻辑**，**不允许**做胜负判定。
- 战斗结果由服务端模拟（**Server-Authoritative Simulation**）。
- 客户端篡改战斗结果 → 服务端校验失败 → 战报无效。

## 7. 异常处理

| 异常 | 处理 |
|---|---|
| 玩家 B 上线后 5 分钟未反手布阵 | AI 镜像兜底 |
| 镜像池无可用布阵 | AI 镜像兜底 |
| 战斗过程中客户端崩溃 | 服务端保留状态 5 分钟，可重连 |
| 服务端模拟超时（> 8 分钟） | 强制判平局 |
| 同段位无可匹配对手 | 跨段位匹配（低段位 +100 / 高段位 -100 模糊化） |

## 8. 合规要求（中日韩三国）

| 国家 | 关键合规点 | 实现要点 |
|---|---|---|
| **中国** | 未成年人保护（限时 + 宵禁）、付费限额 | 实名认证接入；每日 PvP 镜像 ≤ 20 局；夜间 22:00–8:00 禁赛 |
| **日本** | 景品表示法（不准"必胜""最强"宣传）、异步 PvP 不算赌博 | UI 文案预审；战报措辞合规 |
| **韩国** | 未成年限时（深夜禁赛）、强制概率公示 | 与中国相同禁赛窗口 + Gacha 概率页 |
| **通用** | GDPR / CCPA（欧美用户数据可导出 / 删除） | 战报存档支持用户级删除 |

## 9. 性能预算

| 指标 | 目标 |
|---|---|
| 服务端模拟一局 PvP | ≤ 200 ms |
| 镜像匹配查询响应 | ≤ 50 ms（P95） |
| 镜像池规模 | 单段位 ≥ 1000 布阵（保活跃匹配） |
| 战报存储 | 每局 ≤ 50 KB（IndexedDB + 云端备份） |
| 跨段位匹配触发率 | < 5%（在线活跃保活） |

## 10. 数据模型补充

在 `system-interfaces.md` 已有的 `MirrorConfig / MirrorPoolEntry / BattleReport / MirrorMatchResult` 上**新增** 4 个数据模型：

```csharp
// 段位
public enum PvP_Rank {
    Bronze1 = 0, Bronze2 = 1, Bronze3 = 2,
    Silver1, Silver2, Silver3,
    Gold1, Gold2, Gold3,
    Platinum1, Platinum2, Platinum3,
    Diamond1, Diamond2, Diamond3,
    Master
}

// 镜像池条目（含 ELO 信息）
public record MirrorPoolEntry {
    Guid EntryId;
    Guid SourcePlayerId;       // 谁产的布阵
    Guid LayoutId;             // 具体哪个布阵
    DateTime FedAt;
    DateTime ExpiresAt;        // 30 天后自动失效
    int SourceELO;             // 产布阵者当时的 ELO（用于匹配范围计算）
    bool IsAIGenerated;        // 兜底镜像标记
    PvP_Rank SourceRank;
}

// 战报分享
public record BattleReportShare {
    Guid ReportId;
    string DeepLink;           // 防猜测
    DateTime GeneratedAt;
    ShareChannel Channel;      // Wechat / X / InGame
}

// 反作弊标记
public record CheatFlag {
    Guid PlayerId;
    CheatType Type;            // TimeModified / InvalidHero / FrequentDisconnect / ...
    DateTime DetectedAt;
    CheatSeverity Severity;    // Warning / Restrict / Ban
    bool Reviewed;
}
```
